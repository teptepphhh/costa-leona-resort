# Costa Leona Resort - Leona front desk (SAM10 Final Project)

Leona is a virtual front-desk assistant for **Costa Leona Resort**, a *fictional* beach resort. Guests ask about rooms, check-in times, amenities, house rules and directions. The system is informational only: it never books, charges or decides anything about a person. All data is invented.

## What was changed (the reskin)
1. **Identity** - name, sun-and-waves logo, teal/gold theme, favicon, wording (`librechat.yaml`, `branding/`).
2. **Data** - six invented resort documents in `knowledge/` (read from S3 on AWS).
3. **Domain language** - the Leona persona, welcome text and strict answer-only-from-knowledge prompt (`gateway/app.py`, `librechat.yaml`).
4. **AWS integration** - S3 (knowledge base, backups), Systems Manager Parameter Store (secrets), CloudWatch (metrics, logs), SNS (alerts), EventBridge + SSM Run Command (schedules).

## Deploy to AWS (how it was built)
Prerequisites: an AWS account, an IAM user with MFA, a Google AI Studio (Gemini) key, a public copy of this repository. Everything runs in **AWS CloudShell, region ap-southeast-1**, as an admin role (do not use root).
```
git clone https://github.com/teptepphhh/costa-leona-resort.git && cd costa-leona-resort
export AWS_PAGER=""
ALERT_EMAIL=you@example.com REPO_URL=https://github.com/teptepphhh/costa-leona-resort.git bash infra/deploy.sh   # S3, SSM secrets (key typed hidden), SNS, IAM role, security group, log groups, EC2, CloudFront
bash infra/run_on_instance.sh infra/start.sh     # re-render config and restart the stack if needed
bash infra/monitoring.sh                         # 8 CloudWatch alarms + dashboard
bash infra/automation.sh                         # two hourly EventBridge schedules
bash infra/security.sh                           # CloudTrail (GuardDuty if the account plan allows it)
```
Confirm the SNS e-mail subscription, then create the guest-desk user: store a password in `/costaleona/demo_user_password` (SecureString) and run `bash infra/run_on_instance.sh infra/create_demo_user.sh`.
Updates: push to GitHub, then `bash infra/run_on_instance.sh infra/start.sh` (it pulls and restarts).

## Automations (WS-E)
| Automation | Schedule | Script |
|---|---|---|
| MongoDB backup to S3 (kept 14 days) | hourly | `automation/backup.sh` |
| Test questions: pass rate to CloudWatch, e-mail if below 80% | hourly | `automation/smoketest.sh` |

EventBridge rules call SSM Run Command on instances tagged `Project=SAM10` and `Role=web`; each run writes a timestamped line to `/var/log/leona-automation.log` (shipped to CloudWatch Logs).

## Security rules followed
- No secrets in code, config files or git history: `.env` is git-ignored; on AWS the secrets are Parameter Store SecureStrings read at runtime.
- Only invented data is stored or sent to the third-party model.
- Admin rights only through an assumed, MFA-protected role.

## Clean-up (after marking)
Terminate the EC2 instance; delete the CloudFront distribution; empty and delete the S3 buckets; delete Parameter Store parameters, EventBridge rules, CloudWatch alarms/dashboard/log groups, the CloudTrail trail, the SNS topic and IAM roles; revoke the Google AI Studio key; confirm nothing is left and tell the instructor.
